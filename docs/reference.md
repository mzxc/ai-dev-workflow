# 执行参考：规则 / 模板 / 判断标准

> 本文件是执行指令集，不是文档。遇到对应场景时，直接按此执行。

---

## 一、核心执行约束（每次工作前默认激活）

以下约束无需用户提醒，AI 自动遵守：

1. **没写进文件 = 不存在**：决策、约定、排查结论只要没落地为文件，下次对话就会丢失，必须写。
2. **BOOTSTRAP.md 只做导航**：不得向其中塞细节，内容超过 100 行时立即精简。
3. **文档必须与代码同步**：文档描述的结构/行为与代码不符，比没有文档更危险。立即修正不一致。
4. **规则只捕获一次，持续强制**：发现可复用约束就写入 `DECISIONS.md`，之后每行代码都检查。

---

## 二、职责判断

遇到任何任务前，先明确各方职责：

**AI 负责**：实现、测试、文档、记录变更、更新工作流文件、遇到障碍时诊断缺失并写出修复。

**人负责**：优先级（做什么/不做什么）、翻译用户反馈为可验收标准、验证结果、识别"AI 遇困 = 环境缺失"。

> 遇到障碍时，先问"是什么信息/工具/文档缺失让我卡住"，写进仓库，再继续实现。不是重试，是补环境。

---

## 三、AGENTS.md 使用规则

部分工具（Codex、Cursor）识别仓库根目录 `AGENTS.md`。如果项目使用此类工具：

- 在仓库根目录创建 `AGENTS.md`
- 内容来源：`BOOTSTRAP.md` 导航 + `TWEAKS.md` 最核心的几条规则
- 保持 ≤50 行，不重复 `BOOTSTRAP.md` 中已有的完整说明
- `AGENTS.md` 与 `TWEAKS.md` 冲突时，以 `TWEAKS.md` 为准（因为 TWEAKS 是项目级校正）

---

## 四、Golden Principles 维护规则

`DECISIONS.md` 顶部必须维护 `## Golden Principles` 专区。以下情况触发更新：

- 发现同类代码问题出现 ≥2 次 → 提炼为一条 Golden Principle 写入
- 用户明确说"以后都要这样" → 立即写入
- TWEAKS.md 同类纠偏 ≥3 次 → 提炼为 Golden Principle，同时在 TWEAKS 中标注"已提炼"

**Golden Principle 格式要求**（不合格则重写）：
- 一句话，不超过 20 字
- 可操作（AI 能自动判断代码是否违反）
- 人类 5 秒内可判断合规性

**每次代码变更完成后**：扫描本次改动是否违反了任意一条 Golden Principle，违反则修正后再标记完成。

---

## 五、模块文档（modules/*.md）执行规则

### 触发新增条件（命中任一条必须创建新文件）
1. 新增业务模块/子域
2. 模块职责或边界调整（哪怕只是澄清）
3. 跨模块数据流或调用链变化

### 触发更新条件（命中任一条必须更新已有文件）
4. 关键约束变化（幂等、一致性、缓存、降级、权限、SLA）
5. 同一模块在 14 天内被"临时重新探索" ≥2 次

### 执行要求
- 触发后，代码变更与模块文档更新必须在同一轮完成。
- 局部变更也要更新"最近更新时间"和"最近变更影响"段落。
- **未完成模块文档更新，不得标记该子任务为完成。**

---

## 六、熵扫描执行规则

### 被动触发（发现即处理，不得积压）
- 同类逻辑多处重复 → 提取公共方法 + 写入 DECISIONS.md
- 文档与代码不符 → 立即修正文档，不是下次
- TWEAKS.md 同类纠偏 ≥3 次 → 提炼为 Golden Principle
- 某模块每次都要 grep 才能理解 → 立即补 `modules/*.md`

### 主动扫描（每次复杂需求完成后执行一轮）
1. 检查是否有违反 Golden Principles 的代码
2. 检查 TWEAKS.md 是否有 ≥3 次同类纠偏未提炼
3. 检查 `ARCHITECTURE.md` 与实际目录结构是否一致
4. 检查 `BOOTSTRAP.md` 中是否有未描述的新模块

> 持续小额清理 > 积累后的痛苦大重构。每次主动扫描控制在 5 分钟以内，发现什么修什么。

## 七、CURRENT_TASK.md 模板

```markdown
# 当前任务

**项目**: {项目名}
**当前需求**: {需求名 / 修复描述}
**状态**: 进行中 / 阻塞 / 已完成
**执行计划**: 见 demand/exec-plans/active/{文件名}（如有）

## 进度

- [ ] 子需求 1
- [x] 子需求 2（已完成）
- [ ] 子需求 3

## 断点快照（上次停在哪里）

**最后修改的文件**: {完整路径}
**做到一半的事**: {描述，如"接口定义完成，实现未写，controller 未关联"}
**未验证的变更**: {有无改好但未跑测试/未手动验证的代码}

## 阻塞问题

> 无 / 列出卡点，并写明"缺什么才能继续"

## 下一步

1. {具体的第一件事}
2. {第二件事}
```

## 九、CLAUDE.md 自动钩子模板

> 初始化时写入项目根目录 `CLAUDE.md` 末尾。若钩子丢失或被误删，重新追加此内容。

```markdown
## AI 开发工作流自动钩子

如果当前项目根目录存在 `ai-dev-workflow/` 文件夹，则：
1. 自动加载 `ai-dev-workflow` skill
2. 按 skill 中的冷启动流程恢复项目上下文，不得跳过
3. 不要等用户提醒，检测到目录即执行
```
