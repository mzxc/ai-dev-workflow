
   # 参考文档：设计原则 / 模板 / 脚本 / 记忆原则

---

## 核心设计原则（来自 AI 原生工程实践）

### 原则一：AI 看不见的东西等于不存在
凡是没有写入文件的内容，对 AI 来说就是不存在的。所有架构决策、业务规则、技术约定、纠偏记录，**必须落地为 `ai-dev-workflow/` 下的文件**。

### 原则二：地图优于手册
BOOTSTRAP.md 是地图（目录），不是百科全书，保持在 100 行以内。上下文是稀缺资源：信息塞得越多，AI 对关键约束的感知反而越弱。

### 原则三：渐进式披露
AI 从最小稳定入口（BOOTSTRAP.md）出发，按需深入。不要在 BOOTSTRAP.md 中堆砌细节，细节应在恰当的深度文件里。

### 原则四：品味约束，而非实现微管理
关心**边界、正确性、可维护性**，不关心具体实现风格。把团队偏好编码为明确规则（写入 DECISIONS.md 或 TWEAKS.md），而不是每次口头重申。

### 原则五：持续还债，而非集中清理
AI 会复制已有模式——包括坏模式，技术债会自我繁殖。**小增量持续清理 >> 痛苦的周期性大重构。**

## CURRENT_TASK.md 模板

```markdown
# 当前任务

**项目**: {项目名}
**当前需求**: {需求名 / 修复描述}
**状态**: 进行中 / 阻塞 / 已完成
**执行计划**: 见 demand/exec-plans/active/{文件名}（如有）

## 进度

- [ ] 子需求 1
- [x] 子需求 2（已完成）
- [ ] 子需求 3

## 阻塞问题

> 无 / 列出当前卡点

## 下一步

1. {具体要做的第一件事}
2. {第二件事}

## 备注

{其他上下文}
```

## 辅助脚本（scripts/ 目录）

| 脚本 | 用途 | 用法示例 |
|---|---|---|
| `init.sh` | 一键初始化完整目录结构和模板文件 | `bash scripts/init.sh "项目名" "技术栈"` |
| `new-record.sh` | 创建变更记录文件 + 更新 CHANGELOG | `bash scripts/new-record.sh "优化IN参数SQL"` |
| `new-demand.sh` | 创建新需求文档 + 更新 CURRENT_TASK.md | `bash scripts/new-demand.sh "批量导入功能"` |
| `new-exec-plan.sh` | 创建复杂需求执行计划 | `bash scripts/new-exec-plan.sh "需求名" "2026-05-20"` |
| `check.sh` | 会话结束前检查工作流文件更新状态 | `bash scripts/check.sh` |

**平台支持**：macOS ✅ · Linux ✅ · Windows Git Bash ✅ · Windows WSL ✅ · Windows CMD/PowerShell ❌

> 脚本只是辅助工具，不影响 AI 核心工作流程（AI 直接读写 .md 文件）。

## 跨会话记忆原则

1. **不要重复探索**：已探索过的目录结构、模块关系，写入 `ARCHITECTURE.md`
2. **不要重复犯错**：每次被纠正，立即写 `TWEAKS.md`
3. **文档同步代码**：文档与代码不一致比没有文档更危险
4. **定期归档**：`records/` 中超过 3 个月且已上线的记录归档至 `records/archive/`
5. **保持精简**：CURRENT_TASK.md 只保留当前任务；BOOTSTRAP.md 始终 ≤100 行

## 熵管理：持续小清理优于集中大重构

**触发清理的信号**：
- 同类逻辑在多处重复实现
- 文档描述的结构与实际代码不符
- TWEAKS.md 中同一类错误出现 ≥3 次
- 某个模块每次都需要重新探索（说明 modules/*.md 缺失或过时）

**处理方式**：立即在当前任务中顺手修复，修复后更新对应文档，重复模式提炼为 DECISIONS.md 规则。
